# Lab 7 — часткове подання

## Фактичний стан

Це **незавершена лабораторна**, не звіт про успішну міграцію. Підготовлено чернетки `infra/versions.tf`, `auth.tf`, `reports.tf`, `ai.tf`; вони не охоплюють всю інфраструктуру й не підтверджують стан AWS. Архітектурний намір та ризики описано в [ADR 0007](adr/0007-terraform.md). CloudFormation-шаблони залишаються в репозиторії. Авторство чи попереднє застосування чернеток цим звітом не встановлюється.

Terraform CLI 1.10.5 для macOS arm64 завантажено з офіційного releases.hashicorp.com до `/tmp/spry-terraform-1.10.5/terraform`; архів збігається з SHA256SUMS, отриманим із того самого офіційного сервера (окремої перевірки підпису не проводили). `/tmp` тимчасовий. Terraform 1.10.5 та AWS provider 6.71.0 ініціалізовано локально через `terraform init -backend=false`. Після виправлення форматування й дубля provider `terraform fmt -check` і `terraform validate -no-color` пройшли успішно без попереджень. Це лише перевірка синтаксису та схеми, а не доказ відповідності наявним AWS-ресурсам.

Backend не задано, HCP organization/workspace не вибрано або не налаштовано. Публічна сторінка HCP доступна і перенаправляє на login (HTTP 200), але доступ до авторизованого workspace не встановлено й не перевірено; це не доказ глобальної недоступності HCP.

## Чого немає

Немає перевірених live AWS-даних, інвентаризації ресурсів, реального plan чи outputs, імпортів, налаштованого remote state, HCP run, apply, доказу нульового drift або скриншотів успішної міграції. Жодні AWS cloud зміни не виконувалися. Не можна вважати декларації у `.tf` доказом наявності або поточної конфігурації ресурсів. Секрети і значення state до звіту не включено.

## Як продовжити без втрати ресурсів

1. Зберегти наявні чернетки та перевірити права, акаунт, регіони, фактичні CloudFormation stacks, ресурси, залежності і backup лише читанням. Узгодити власника, scope, вікно робіт і rollback; заморозити конкурентні зміни.
2. В окремому тестовому середовищі перевірити відповідність чернеток шаблонам і фактичним ресурсам. Не запускати `apply` на неперевірених ресурсах.
3. Отримати авторизований HCP workspace або погодити інший захищений backend із блокуванням; захистити state і plan, оскільки навіть sensitive-значення можуть у них зберігатися. Налаштувати безпечну передачу секретів та доступи. Не створювати локальний state як заміну спільному без погодженого плану перенесення.
4. Для кожного існуючого ресурсу визначити ID, адресу Terraform і підтримуваний спосіб виведення з CloudFormation зі збереженням фізичного ресурсу; імпорт не зупиняє управління CloudFormation автоматично. Не видаляти stack і не допускати двох одночасних власників. Спочатку перевірити процес на тестовому середовищі.
5. Після контрольованого перенесення власності й імпорту переглянути plan, зупинитися при неочікуваному create/delete/replace і узгодити будь-які зміни перед apply. Перевірити роботу та резервні копії; окремо підтвердити захист Cognito, S3, бази й секретів. Докладніше — ADR 0007.
