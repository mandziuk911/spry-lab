# ADR 0006: suggestion-only agenda parsing with Amazon Bedrock

**Status:** implemented; deployment and real model access require separate verification.
**Context:** Lab 6, Spry, 29 October 2026.

## Context

Meeting agendas arrive as Ukrainian/English email, chat or notes instead of complete forms. The user needs a quick editable draft but should not trust invented people, dates, or instructions copied from untrusted text. A parse takes seconds and consumes billed tokens. The deployed Spry API and RDS are in `eu-north-1` private-network architecture with no NAT gateway; the lab asks for Bedrock access in `us-east-1`. The parser needs only text, not database access. We retain the existing RDS PostgreSQL database rather than claiming it is Aurora.

## Decision

A separate ARM64 Lambda container outside any VPC calls the configured Bedrock model in `us-east-1`. `PARSER_MODEL` is configuration, not hardcoded business logic; the provider-neutral Bedrock Converse path supports Amazon Nova, while the Bedrock Mantle client supports Claude. **The chosen default `us.amazon.nova-micro-v1:0` is provisional until an actual access check and `make llm-hello` succeed; availability and account-specific agreement status are not assumed.** If and only if the instructor explicitly allows an alternative and access is verified, use that model and document the actual reason instead of claiming unverified Claude quota values.

The browser sends a Cognito access token, text, today's local date and IANA timezone to the Function URL. Lambda validates Cognito RS256 signatures, issuer, expiry, token use and client ID through the trusted pool's JWKS. It limits text to 10,000 characters before calling the model. Cognito's public Function URL does not itself authenticate: Lambda's verifier is mandatory. CORS permits configured site origin only; CORS does not prevent direct non-browser calls. A bounded Lambda reserved concurrency helps limit concurrent spend, **not** per-user usage; production requires durable per-user throttling and quotas.

A prompt delimits pasted text as data and requests a single `record_agenda` tool response. The application validates a bounded Pydantic schema, makes at most one repair call, and rejects absent/invented owners when they are not literally present in the source. Literal presence alone is not a complete defense: a malicious instruction itself may contain an attacker's address. Ambiguous dates are left blank where possible and are visibly flagged for human review. There is no LLM write tool. The browser shows a form with per-field suggestion labels; only explicit Save calls the existing authenticated API, which validates and stores the final agenda plus original AI suggestion, model and prompt version. This allows manual correction and later evaluation. The base application currently has a shared authenticated desk, **not** tenant isolation; do not represent it as an org-isolated RAG system.

## Alternatives considered

1. **Bedrock from the VPC-attached main API via interface endpoint.** Keeps the call in the private network but adds an always-on endpoint and exposes otherwise unrelated API reliability to model latency. The supplied comparison is `$7.30/month` for one endpoint; actual endpoint, availability zone and data processing charges vary. Here the parser has no database need, so the isolated Lambda is simpler and idle inference cost is zero.
2. **Claude API directly.** Avoids a Bedrock VPC endpoint and may expose vendor features sooner, but requires an external API key, another billing relationship and secret management. Bedrock uses an AWS IAM role and the existing AWS budget. This is not a claim that Bedrock is universally cheaper or that Claude is inaccessible before an account check.
3. **Regular expressions.** Cheap, deterministic and useful for rigid fields, but brittle across Ukrainian, English, conversational emails, varying layouts and relative dates. Regex remains useful for input limits or deterministic verification, not for full language understanding.

## Consequences and prices

In the official AWS public price list for **Amazon Nova Micro on-demand in us-east-1**, regional input is **$0.035 per million tokens** and output **$0.14 per million tokens** ([AWS Bedrock pricing](https://aws.amazon.com/bedrock/pricing/), [AWS public region price index](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonBedrock/current/us-east-1/index.json)). Price depends on actual model, inference mode, region and current AWS terms; verify the selected inference profile before treating this rate as the bill. Model cost estimate per call is `(input_tokens × 0.035 + output_tokens × 0.14) / 1,000,000`; repair calls' reported tokens are added. Reported per-call cost is an **estimate**, excluding Lambda, logs, data transfer, free-tier effects and any provider charge for timed-out calls without usage. Prices are configuration in Lambda, not guessed for unknown models. Real measured per-parse cost and monthly projection belong in generated evaluation evidence, not invented here.

The CloudWatch event `agenda_parsed` contains user subject, model, prompt version, input/output token counts, wall-clock latency and estimated dollars; it does not contain the pasted text or JWT. Failed calls emit `agenda_parse_failed` with any usage known from completed calls. SDK timeouts may still be billed, even when usage is unknown. A $5 monthly AWS Budget emails the owner; budget alarms can be delayed and are **not** a hard cap. Existing ECS, RDS, Lambda, networking and credits still cost money. After grading, the operator should explicitly destroy the AI stacks and review all other course stacks and billing; no automatic destructive action is performed.

When Bedrock is throttled, returns an invalid tool response or is unavailable, the browser distinguishes the error and the user can type an agenda manually. Other Spry functionality and the API remain available. Cancel aborts the browser's request; it **cannot guarantee** that Lambda or Bedrock stops computing or billing. Model output is only a suggestion and a plausible date or source-present owner can still be wrong; the person is responsible for checking every field.

Evaluation is a separate engineering activity: run the same saved, consented 500-source cases against v1 and v2, use human-corrected final agendas as a noisy gold standard, split by organization/time and keep a held-out test set, compare exact/semantic topic extraction, owner assignment, date accuracy, unsupported-value rate, empty-field precision, latency and cost with per-case paired statistics. Blind adjudicate ambiguous cases and do not train/tune on the held-out set. Store the input, relevant timezone/date context and prompt/model versions under appropriate retention/privacy controls; `ai_suggestion` alone without the original text/context is insufficient to rerun a prompt.
